## The quarantined row (Requirement 1.7, 1.10)

Exactly one row is quarantined, not migrated: CSV row 2668, `season_year=2023,
meet_number=2, division=Frosh, team_name="St Agnes"`. It has no
`athlete_full_name`, `bib`, or `finish_time_s` -- instead it carries
spreadsheet-scoring columns (`Final Score: 9`, `TB: 27:16.4`, `Finisher 1-10:
[1,3,5,7,19,24,25,35,36,48]`), i.e. it is a **team-level scoring summary**,
not an individual result. This is the documented 2023 Meet 2 gap (R1.10): 547
of 548 total 2023-Meet-2-scoped rows are simply absent from the source
entirely (only this one team-only artifact exists), and it stays a gap --
nothing is inferred or filled in.

## The dominant "observation": a bug in the baseline's own reference calculation

31 of the 34 observations are `team_scores` rows present in the baseline but
not reproduced by `v_team_scores`, and every one of them is 2023 Meet 1.
Investigating: **2023 Meet 1 has no `place_overall` value at all -- 548 of
548 rows are null.** `scripts/freeze_baseline.py`'s reference calculation
sums `place_overall` with `pandas.Series.sum()`, and pandas sums an all-null
column as `0.0` (its default `skipna=True` behavior), not `NaN` and not an
error. The result: the frozen baseline records `"score": 0` for all 31
team/race groups in 2023 Meet 1 -- a value that looks like a real (if
unusually good) team score but is actually "we have no place data to sum."

`v_team_scores` requires a non-null `place_overall` before a result counts
toward a team's score at all (`WHERE r.place_overall IS NOT NULL`), so it
produces no row for these 31 keys rather than reproduce the artifact. This
is judged the correct behavior, not a discrepancy to fix: Requirement 1.7
requires representing a gap explicitly rather than fabricating a value, and
"the team's score is 0" is not what the source data says -- "we don't know
the team's score" is.

The remaining 3 observations are the accounting identity confirming the
quarantined row explains the one-row gap between `total_records` (4204) and
canonical `results` (4203), reported once by `counts` and once each for the
`by_division` breakdown (the quarantined row's division is `Frosh`).

## Also discovered and fixed while migrating real data

- **`grade` CHECK constraint was wrong.** Migration 0002 (Task 4) originally
  constrained `grade BETWEEN 6 AND 12`, assuming a high-school-only league.
  The frozen baseline is a K-8 CYO youth league (divisions `2nd Grade` /
  `Frosh` / `JV` / `Varsity`, grades 2-8 observed). Fixed to
  `BETWEEN 1 AND 12` before migrating -- caught by attempting the real
  migration, not by code review.
- **An unstandardized team-name variant survives in the frozen CSV.**
  `standardize_team_names.py`'s mapping has the key `"St. Rita Parish
  Alexandria"` (plain space), but the actual frozen CSV contains
  `"St. Rita Parish\xa0Alexandria"` (U+00A0 non-breaking space) for a subset
  of 2023 rows. The exact-string `.replace()` the legacy script used never
  matched it, so it was never standardized to `"St Rita"`. This migration
  preserves it as its own distinct school (R1.8/1.9: migrate exactly as the
  baseline holds it), and it is a source of 6 of the 31 `team_scores`
  "observations" that are actually genuine team/race groups (not the
  score-of-0 artifact) that never reached 5 finishers under that specific
  spelling.
